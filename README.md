# Tether · 情绪记录与自我调节（Web 版）

按《AI + 海外情绪记录与自我调节工具 · 产品计划书》实现的可运行前后端。
定位仍是 **wellness**：记录 + 自我调节，不做诊断、不做治疗。

```
一键记录  →  按情绪分支立刻干预  →  事后补填原因与强度  →  按严重程度排序  →  规则归因总结（付费层）
```

## 运行

零第三方依赖，只需要 Python 3.10+：

```bash
python backend/server.py            # http://127.0.0.1:8000
python backend/server.py 8080       # 换端口
```

Windows 也可以双击 `start.bat`。

首次进入是空库。首页有「载入两周演示数据」（28 条），可以在「我的 → 数据」里随时清空。

### 跑在服务器上

整个应用是**一个 Python 进程**：`/api` 和前端静态文件都由它提供，不需要再单独配一个静态站点。

```bash
# 面板里（宝塔 / 1Panel 等）选「Python 项目」
# 项目目录 = 仓库根目录（不是 backend/），启动命令：
python backend/server.py 8000
```

- `PORT` 环境变量等价于命令行端口参数。
- `HOST` 默认 `127.0.0.1`（前面挂 Nginx 反代时就用默认值）；要在容器里直接对外，设成 `0.0.0.0`。
- `.env`（AI key）不在 git 里，部署后要手动放一份，否则 Pro 层会静默降级成规则版。
- `backend/data/tether.db` 首次启动自动创建；要重置就删掉它。
- **没有登录和鉴权**：谁能访问到这个端口，谁就能读写全部记录。公网部署前请在前面加一层访问控制。

## 计划书 → 实现对照

| 计划书要求 | 落地情况 |
|---|---|
| 极低摩擦：一键选情绪，不强制写原因 | 点情绪立即建记录并进入干预，原因与强度在干预**之后**补 |
| 按严重程度排序，严重的排前面 | 列表 `severity DESC`，未评估的记录排在最后并标「未补填」 |
| 愤怒：降唤醒优先 | 一次长呼气 8s → 4-6 呼吸 30s（动画圆） → 一句断念 10s |
| 伤心：陪伴 + 极小身体动作，不推断念 | 手放胸口 30s → 允许它在这儿 20s，无「看着念头走」 |
| 绝望：不走断念，托底 + 本地危机热线 | 独立 `despair` 分支，危机卡首屏可见，`tel:` 直接拨号，永久免费 |
| 危机资源不设付费墙 | 前端无任何 plan 判断，后端也从不校验订阅 |
| AI 总结：颗粒度到场景 + 时段 | Pro 层由大模型写：分布（几次、落在哪个时段）→ 强度（和整体均值差多少）→ 下一步（按「指向什么 × 主导情绪」给具体动作）。次数/时段由代码算好，模型只引用不加总 |
| 归因要说得住 | 场景分三类：外部场景 / 内在状态 / 身体状态。只有外部场景才说「下次它再来」；内在状态（自我评价、反复想）走托底或延长呼气；身体状态建议单独记录。这条写进提示词的硬约束 |
| 免费层：基础统计 | 记录数 / 平均强度 / 有记录天数 / 情绪分布 / 高频原因 |
| 付费层：归因 + 场景提醒 + 趋势 | `plan=pro` 时解锁，免费时给 1 条示例 + 解锁卡 |
| 记录量门槛（20—30 条） | 不足 20 条时显示进度条与「还差 N 条」，不硬凑结论 |
| 干预体感要可验证 | 每轮干预结束问「有没有缓下来一点」，进入「干预反馈」统计 |
| 合规文案 | 首页脚注 + 关于页免责声明，全站无「治疗 / 诊断 / 缓解抑郁」表述 |

额外做了：中英双语（英语市场首选）、地区化危机热线（US/CA/UK/AU/EU）、JSON/CSV 导出、语音输入原因（浏览器支持时）。

## Pro 层的 AI 分析

`plan=pro` 时，「总结」页的结论由大模型现写，不再套模板；免费层仍是规则版 + 1 条示例。

### 配置

把 `.env.example` 复制成 `.env`（已被 `.gitignore` 排除，不会进仓库），填入任意 OpenAI 兼容服务的 key：

```ini
TETHER_AI_API_KEY=sk-...
TETHER_AI_BASE_URL=https://api.deepseek.com/v1
TETHER_AI_MODEL=deepseek-flash
```

没配 key 时整站静默走规则版，界面上不会出现空块或报错。

### 谁负责什么

| 内容 | 归属 | 原因 |
|---|---|---|
| 次数、时段分布、均值、严重条数、峰值、干预率 | 代码（`insights.py`） | 数字必须和列表对得上，不能让模型自己加总 |
| 哪条最值得先看（`focus`）、总览、每条归因、场景提醒、下一步动作 | 模型（`ai.py`） | 这部分原来是写死的模板，换个用户就千篇一律 |

模型只替换句子：卡片顺序、颜色、计数仍由前端按代码给的结构渲染。

### 出问题时

任何一步失败（没 key、超时、5xx、输出不是合法 JSON、被截断、出现诊断类表述）都退回规则版，
卡片顶部显示「规则版」标记和重试按钮，不会白屏。诊断类表述是硬拦截——命中「抑郁症 / 确诊 /
药物 / 剂量」这类词整份作废，因为产品定位就是不做诊断。

### 成本与延迟

- 首次分析约 7—10 秒（`reasoning_effort=high`）。结果按「数据指纹」缓存：记录、窗口、语言任一
  变化才重算，来回翻页不会重复调用。
- 一次约 4.5k tokens（含推理过程）。想更快更省，把 `TETHER_AI_REASONING_EFFORT` 调成 `low`。
- 发出去的是聚合结果 + 最多 60 条记录的摘要（原因截 40 字、备注截 60 字），界面上有明示。

### 接口

- `GET /api/insights` — 永远快。`ai.status` ∈ `pro / off / insufficient / pending / ready`；
  为 `pending` 时前端再调下面这个。
- `POST /api/insights/analyze` — 真正生成；`{"days":14,"force":true}` 可强制重写。
  失败也返回 200，只是 `ai.status=error` 并附带规则版正文。

## 前端的几个取舍

| 做法 | 为什么 |
|---|---|
| 引导计时走 `requestAnimationFrame` + 时间戳，不用 `setTimeout` 累加 | 标签页切到后台时定时器被节流，30 秒的降唤醒会拖成一分多钟，呼吸节律也跟着偏；按真实时间算就不会漂 |
| 深 / 浅 / 跟随系统三套外观，首屏内联脚本定主题 | 情绪记录大量发生在夜里；主题在 CSS 生效前就定好，刷新不会闪白 |
| 情绪色和强度色在深色下按 HSL 提亮 | 这些颜色是为浅底调的，直接铺到暖炭底上会糊成一团。后端数据不动，前端自适应 |
| 视图进 `history`，浮层也进 | 手机上的返回手势先关浮层，而不是直接退出应用 |
| 筛选只重绘列表容器 | 否则每点一次筛选，页面都滚回顶部 |
| 列表分页（40 条一屏） | 演示数据只有 28 条，但真用几个月就是上千条 |
| 浮层做焦点陷阱，`#view` 不再是 live region | 原来整个视图挂着 `aria-live`，每次重绘屏幕阅读器都会复述整页 |
| 总结页加 14/30 天强度走势 | 用本地已有记录算，不多发一次请求 |
| 日期格式化器按语言缓存，结果按记录缓存 | `toLocaleTimeString` 每次调用都重建一个 Intl 格式化器，一条记录两次。1200 条记录的日期格式化从 ~89ms 降到 ~0.04ms（缓存命中后），重绘才不会卡 |
| 情绪色的深色换算、HTML 转义表都提到模块级 | 一次列表重绘里同一个色值会被问上百次，原来每次都走一遍 HSL 来回换算 |
| 引导进度条由 rAF 推进，并去掉 CSS transition | 每帧写 width 会新开一段 0.35s 动画，进度条一直追在真实进度后面；节点引用也抓一次就够，不用每帧 querySelector |
| 点情绪瓦片有并发锁 | 慢网络下双击会落下两条记录 |
| `role="dialog"` 直接挂在 `#overlay` 上 | 原来套了一层 `display:contents` 的 div，而 `display:contents` 会连盒子一起去掉，部分浏览器会把它的 role 一并丢掉 |
| 记录改动后主动让总结过期 | 原来只在切统计窗口时重拉，「记几条 → 回总结页」看到的还是进页面时那份数字 |
| 每个视图记自己的滚动位置，再点当前 tab 回顶部 | 视图整块重绘，浏览器自带的滚动恢复帮不上忙 |
| 单条动态 `theme-color`，不用 media 查询 | 系统深色而用户手动选浅色时，状态栏会按系统那条走，和页面是两个颜色 |
| 浮层改动后不再整表重拉 | 本地状态已经改好了，关一次浮层少一次 500 条的请求 |
| service worker 用网络优先 + 缓存兜底 | 装到主屏后能离线打开外壳；但这是本地 demo，改一行 JS 就该立刻生效，不能被缓存挡住 |

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/meta` | 情绪列表、强度标签、地区、定价、免责声明 |
| POST | `/api/entries` | 建记录，返回该情绪的干预脚本 |
| GET | `/api/entries` | 列表（`sort=severity\|time`、`emotion`、`days`、`unfilled`） |
| PATCH | `/api/entries/{id}` | 补填强度 / 原因 |
| DELETE | `/api/entries/{id}` · `/api/entries` | 删一条 / 清空 |
| GET | `/api/interventions/{emotion}` | 单独取干预内容 |
| POST | `/api/entries/{id}/intervention` | 记录干预完成与「有没有缓下来」 |
| GET | `/api/stats/basic` | 免费层统计 |
| GET | `/api/insights` | 归因总结（按订阅状态加锁） |
| GET/POST/PATCH | `/api/account*` | 订阅状态（演示，无真实支付）、语言、地区 |
| GET | `/api/crisis` | 按地区的危机资源 |
| GET | `/api/export?format=json\|csv` | 导出 |
| POST | `/api/demo/seed` | 写入两周演示数据 |

所有接口带 `?lang=zh|en`。

## 还没做的（有意留白）

- **真实支付**：订阅只是本地状态，用来验证免费层与付费层的切分位置。
- **账号体系**：单用户本地库，没有登录（也就没有跨设备同步）。
- **推送**：峰值干预是用户点情绪后即时触发，没有主动推送。
- **自定义情绪标签**：情绪集合目前固定在 7 个，避免归因标签爆炸。
- **正性情绪不参与归因**：「挺好 / 平静」会被统计进情绪分布，但不进入归因聚合——不然一条「和朋友吃饭，挺好」会把「亲密关系」那组的均值拉下来。
- **原生 App**：iOS 版本要等手动验证阶段跑通（计划书第 7 节）。

## 注意

数据是明文 SQLite，存在 `backend/data/tether.db`，只在这台机器上。
这是演示实现，不能直接上线给别人用——上线前至少要有隐私政策、账号隔离、传输加密。
