# 国际化执行计划

面向「国内 + 海外同时可用」的产品改造。状态日期：2026-11-22。

## 一句话定位

产品解决的是**双向的语言不对称**：母语里精确的情绪，换到第二语言就变模糊；对方用非母语说来的话，也容易被读错。中国学生在柏林、美国经理在上海，遇到的是同一件事。

对外表述（中英各 100 字/词）见 [README](../README.md) 与本文档末尾；禁用词：therapy / diagnosis / treatment / cure / patient（中文：治疗、诊断、疗程、病人）。

## 四层「双向」

| 层 | 单向的现状 | 目标 |
|---|---|---|
| 表达 | 只会把「我想说」写出去 | 加上「听懂对方」 |
| 语言 | `zh → en` | 任意方向，语言对由配置决定 |
| 用户 | 默认按中国用户设计 | 中英用户同等第一等 |
| 收入 | 只有兑换码 | 定价 / B2B 采购 |

## 阶段与状态

### 阶段 0：对外表述（已完成）

- 中英 100 字/词表述、术语表、禁用词表。
- 交付位置：README「跨语言表达」段落 + `docs/cross-border-scenes.md`。

### 阶段 1.1 语言基础设施（部分完成）

已完成：

- **界面语言跟随浏览器**：优先级为 本机选择 > 账号明确设置（`lang_set`）> 浏览器语言 > 中文；新增 `users.lang_set` 列区分"默认值"和"用户选过"，老库自动迁移。
- **危机资源可追溯**：每个地区带 `verified_at` 与 `source`，接口下发、界面显示核对日期；不变式写进测试（可拨号或有链接、每个地区有 https 来源、中英文齐全）。清单与复核规则见 [危机资源](crisis-resources.md)。

未完成：

| 项目 | 现状 | 目标 |
|---|---|---|
| 目标语言编码 | `zh` / `en` / `ja`… 短代码 | BCP-47（`zh-Hans`、`zh-Hant`），涉及服务器与前端多处 |
| 日期/数字 | 已有 `zh-CN` / `en-US` 分支 | 统一走 `Intl` 与浏览器 locale，不手拼格式 |

### 阶段 1.2 反向链路「听懂对方」（已完成）

- 接口 `POST /api/expression/interpret`。
- 输出：字面意思、语气档、可能的潜台词、1—2 条可复制回复、最多两条文化提示。
- 硬规则：事实与推测分栏；不判断对方人格；整条命中临床表述即拒绝；危机表达不解读潜台词。
- 规则细节与字段表见 [跨境表达场景](cross-border-scenes.md) 的「反向」一节。

### 阶段 1.3 语用规则数据化（已完成）

四维语用表已落地（`backend/app/pragmatics.py`）：`directness` / `honorific` / `face_cost` / `conclusion_position`。

- 每种语言一条配置（中、英、日、韩、德），语气与对象只做加减并夹在 1—3；
- 语言是否可选由 `TETHER_LANGUAGES` 决定（默认 `zh,en`），`/api/meta` 下发列表，前端下拉框自动跟随；
- 生成与解读两条链路都会把这组维度作为结构化事实传给模型，提示词不再内置某个国家的习惯；
- 加一门语言 = 加一条配置 + 改一个环境变量，不改接口、提示词和前端。

实测证据（同一句拒绝、同语气同对象，只换目标语言）：

| 目标语言 | 结构 |
|---|---|
| 英语 | 结论第一句 → 一层缓冲 → 给替代时间 |
| 日语 | 先致意 → 转述请求 → 说明今晚困难 → 请求改到明早（敬语全开） |

顺带修掉一个只有真调用才会暴露的问题：目标语言名原来写死成「英文否则简体中文」，选日语仍输出中文；现在语言名来自配置表（`model_name`），未知语言回落到英语而不是静默变中文。

未完成：每种语言的真实语料评测（语气保持率、采纳率），见阶段 2。

### 阶段 2：验证（未开始）

1. 10 个双向深访：5 个中国人在海外 + 5 个外国人在中国，问「上一次你用非母语说不出话，是什么时候、后来怎么办」。
2. 双语 landing A/B：同一产品两套文案（「情绪日记」vs「把说不出口的那句说出来」）。
3. 埋点：复制率、二次生成率、周闭环次数、4 周回访。不报 DAU。

### 阶段 3：商业模式（未开始）

- B2B 先走：高校国际学生办公室、跨境团队 HR/EAP、语言学校。
- B2C 后走：只把「跨语言沟通」做成 Pro 功能，单一卖点好定价。
- 海外客户第一个问题会是数据流：自托管 + 离线是卖点，配套数据流图、删除/导出演示、DPA 模板。

## 明确不做

- 不加 10 种语言的界面（先把规则抽象对）。
- 不做站内社区（审核与合规成本）。
- 不做临床量表/测评（进入医疗器械监管）。
- 这一轮不做支付。

## 手机端（最终形态）

产品最终形态是手机应用，浏览器只是调试环境。已落地：可安装 PWA、maskable 图标、安全区避让、软键盘布局收缩、16px 输入框、44px 触控目标、应用内添加到主屏入口；并新增可重复的手机端验收（5 个设备视口，0 错误 0 提醒）。详见 [手机端](mobile.md)。

走向应用商店的下一步是 Capacitor 包装，主要工作量在 WebView 的同源 API 与 Cookie 携带策略，界面无需重写。

## 对外表述（定稿）

**中文（102 字）**：痛点：母语里说得清的情绪，换到外语只剩一句「I'm fine」；记录工具只留痕，不改变。突破：8 类日常场景做成双向语用规则，模型只表达，数字归代码，临床表述直接拒绝。价值：90 秒闭环，每周一张证据卡；可自托管离线，双语通用，零第三方依赖。

**English (103 words)**：Pain: feelings are precise in your first language and blurry in your second. When you have to explain yourself, all you have is "I'm fine." A Chinese student in Berlin and an American manager in Shanghai hit the same wall. Breakthrough: eight everyday situations, from asking for more time to clearing up a conflict, turned into pragmatic rules that work both ways. The model writes; the code owns every number; clinical language is rejected outright. Value: a 90-second loop. Write it, say it to them, rate a practice before and after, get a weekly evidence card. Self-hosted, offline-capable, in your language and theirs.
