# 问卷驱动的项目改进

依据 2026-11-17 提供的《日常情绪表达与安慰需求调查问卷》默认报告和 AI 报告。本次共 11 份答卷，Q4–Q16 各有 10 人回答；全部年龄为 18–24 岁，生活状态题有 8 人在校。以下是针对当前项目的探索性优化，不将小样本偏好当成总体结论。

## 从证据到实现

| 问卷信号 | 本轮实现 |
| --- | --- |
| Q12：7/10 选择自由表达；4/10 希望自己选择倾听或建议 | 登录前与首页直接输入；三种可切换的整理方式。明确标示本地提示，不伪装成真人或 AI 回应。 |
| Q13：6/10 反感提前说教；6/10 反感追问细节 | 默认「只想表达」，没有追问；整理问题均可留空。选择情绪后先选择是否尝试引导。 |
| Q14：7/10 担心保存、泄露或其他用途；Q15 保存偏好分散 | 默认页面内存暂留；本机 TXT 下载；账号保存需主动选择并确认，真实说明服务器明文存储及可选 AI 分析的数据流。 |
| Q4：5/10 涉及学习考试，4/10 涉及人际关系 | 记录快捷场景增加考试、作业、未来不确定和求职，保留自由输入。 |
| Q12：没有人把保存回顾选入优先三项 | 既有记录和总结保留；新增入口首先支持当次表达，不要求注册或形成长期记录。 |

## 已实现的边界

自由表达正文最多 500 字，四项可选整理答案各最多 160 字。所有已填答案在切换方式后保留，下载和账号保存都包含它们。账号保存复用 cause / note 字段，无数据库迁移，不更改旧记录。

只想表达模式没有生成回复；其他模式是固定的可选自我整理提示。未新增 AI 对话、真人倾听、社区或自动发送给熟人的能力。用户表达的内容不会在这条流程中发送给模型。已有 Pro 总结仍是独立、手动启动的功能，保存前如实提示其可能处理记录摘要。

「本机下载」是显式生成文件，不是浏览器自动保存或端到端加密。页面内存暂留与服务器记录明确区分。关闭浮层不等于立即清除原稿；页面提供单独清除入口及说明。

保存失败时保留完整请求，锁定原稿，重试同一请求标识；收到成功确认后清空本页草稿。服务器已保存但列表刷新失败时，明确报告保存成功。既有账号隔离、缓存清理、导入导出、练习与历史数据逻辑保持不变。

## 验收

逻辑测试（不依赖浏览器、不访问真实数据库）：

```sh
node tests/run_frontend.mjs
python -m unittest discover -s tests -v
```

真实浏览器测试先为服务指定独立的 `TETHER_DATA_DIR`，在 127.0.0.1:8766 启动；不要使用真实业务库。`tests/expression_browser.cjs` 使用 Playwright 与 Edge，`PLAYWRIGHT_MODULE` 可指定包路径，`EDGE_EXECUTABLE` 可指定浏览器，`TETHER_TEST_URL` 可覆盖测试服务地址。该测试会创建测试账号和记录。

```sh
node tests/expression_browser.cjs
```

覆盖：游客输入不发写请求、不写入浏览器存储；切换模式与返回保留原稿；下载与清除；账号保存前的选择和确认；安全展示用户文本；保存后查看编辑备注；服务器已提交但响应丢失时重试不重复；情绪选择不自动引导；320/390 像素手机与桌面、中英文、深浅主题。

## 下一轮验证

先邀请目标用户试用，观察是否能找到表达入口、理解不同保存方式，并在不需要引导时顺利结束。记录反馈前应另行明确告知与获得同意；本轮没有加入内容采集或分析埋点。

真人、熟人分享和 AI 回应的偏好尚不足以确定具体实现，适合后续用可交互原型分别验证。后续问卷应补齐经历题的时间锚点与跳转，拆分文字/语音和隐私选项。明确有过情绪理解需求的是 6/11，不把「记不清」当作有需求。
