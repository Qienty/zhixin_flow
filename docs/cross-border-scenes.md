# 跨境表达：场景、槽位与输出规则

面向「要发一条难发的消息」的跨境场景。它不是翻译：输入是零散的槽位，输出是一段**可以直接复制发出去**的话，外加一个不同语气的备选和最多两条语气提示。

入口：登录后首页「说给对方听」。接口：`POST /api/expression/translate`。

## 为什么做成场景而不是翻译框

- 翻译框要求用户先写好一段完整的中文，这正是需要帮助的人做不到的一步。
- 「翻译」在用户心里等于 DeepL，没有打开理由；「要跟导师说要延期」才是打开理由。
- 场景把跨文化语用（敬语层级、结论位置、禁忌表达）变成可枚举、可评测的规则，而不是一句「我们用了大模型」。

## 8 个场景

| id | 中文 | 英文 | 结构 |
|---|---|---|---|
| `deadline` | 要延期 | Ask for more time | 来意 → 原定时间 → 新的时间 → 承诺或补救 |
| `decline` | 要拒绝 | Say no | 明确结论 → 简短理由 → 可选替代 |
| `apologize` | 要道歉 | Apologize | 具体行为 → 影响 → 补救 |
| `ask_help` | 要求助 | Ask for help | 具体请求 → 时间 → 为什么找你 |
| `conflict` | 说清一次冲突 | Clear up a conflict | 事实 → 感受 → 具体请求 |
| `bad_news` | 报一个坏消息 | Deliver bad news | 结论 → 影响范围 → 已做的应对 → 下一步 |
| `negotiate` | 争取一下 | Negotiate | 价值或处境 → 具体请求 → 可接受的替代 |
| `boundary` | 划个边界 | Set a boundary | 我需要什么 → 一个可执行的安排 |

## 槽位（`details`）

最多 4 个，每个 200 字符，全部可留空但要至少填一个：

| 字段 | 问的是什么 |
|---|---|
| `what` | 发生了什么 |
| `when` | 原来的时间 / 现在的情况 |
| `want` | 你希望对方怎么做 |
| `extra` | 想补充的 |

## 语气与对象

- `tone`：`polite`（稳妥）/ `direct`（直接）/ `close`（亲近）。
- `relation`：`professor` / `manager` / `client` / `peer` / `friend`。它决定称谓与敬语层级，也决定结论放在第一句还是第二句。

## 输出

```json
{
  "text": "主版本",
  "target_lang": "en",
  "intent": "share|ask_listening|ask_space|ask_advice|unclear",
  "cultural_notes": ["最多两条"],
  "alternatives": [{"tone": "direct", "text": "另一种语气"}],
  "safety": "ok"
}
```

服务端校验：场景/语气/对象必须在白名单内；`details` 不认识的字段直接 400；备选版本必须与主版本不同、语气不同、长度不超过 1200，且逐条过一遍临床表述检查。命中「诊断、药物、治疗」一类词整条丢弃，宁可不给，也不给错。

## 不做的事

- 不替用户发送，不存进账号（结果只在当前页面）。
- 不推断用户的人格、关系或心理状态。
- 不添加用户没有填的事实：时间、原因、承诺都只能来自槽位。
- 不做临床建议；危机表达仍走危机资源入口。

## 可评测的指标

这些指标用来证明「跨文化语用」不是口号：

- **采纳率**：生成后点了复制 / 生成次数。
- **二次修改率**：复制后回来重新生成的次数。
- **语气保持率**：同一槽位换 `tone` 后，结论位置与致歉强度是否按预期变化。
- **语言合规率**：备选版本被安全校验丢弃的比例。

建议先人工标注 30—50 条真实场景（留学生、跨境团队），再对比通用模型基线，报告上述四项而不是「感觉更自然」。
