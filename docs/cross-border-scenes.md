# 跨境表达：场景、槽位与输出规则

面向「要发一条难发的消息」的跨境场景。它不是翻译：输入是零散的槽位，输出是一段**可以直接复制发出去**的话，外加一个不同语气的备选和最多两条语气提示。

入口：登录后首页「说给对方听」。接口：`POST /api/expression/translate`。

## 为什么做成场景而不是翻译框

- 翻译框要求用户先写好一段完整的中文，这正是需要帮助的人做不到的一步。
- 「翻译」在用户心里等于 DeepL，没有打开理由；「要跟导师说要延期」才是打开理由。
- 场景把跨文化语用（敬语层级、结论位置、禁忌表达）变成可枚举、可评测的规则，而不是一句「我们用了大模型」。

## 8 个场景

| id | 中文 | 英文 | 结构 |
|---|---|---|---|
| `deadline` | 要延期 | Ask for more time | 来意 → 原定时间 → 新的时间 → 承诺或补救 |
| `decline` | 要拒绝 | Say no | 明确结论 → 简短理由 → 可选替代 |
| `apologize` | 要道歉 | Apologize | 具体行为 → 影响 → 补救 |
| `ask_help` | 要求助 | Ask for help | 具体请求 → 时间 → 为什么找你 |
| `conflict` | 说清一次冲突 | Clear up a conflict | 事实 → 感受 → 具体请求 |
| `bad_news` | 报一个坏消息 | Deliver bad news | 结论 → 影响范围 → 已做的应对 → 下一步 |
| `negotiate` | 争取一下 | Negotiate | 价值或处境 → 具体请求 → 可接受的替代 |
| `boundary` | 划个边界 | Set a boundary | 我需要什么 → 一个可执行的安排 |

## 槽位（`details`）

最多 4 个，每个 200 字符，全部可留空但要至少填一个：

| 字段 | 问的是什么 |
|---|---|
| `what` | 发生了什么 |
| `when` | 原来的时间 / 现在的情况 |
| `want` | 你希望对方怎么做 |
| `extra` | 想补充的 |

## 语用四维（不是按国家写死）

每种语言在 `backend/app/pragmatics.py` 里只有一条数据，四个维度：

| 维度 | 取值 | 决定什么 |
|---|---|---|
| `directness` | 1—3 | 句子有多直接、要不要留余地 |
| `honorific` | 1—3 | 称谓与敬语层级 |
| `face_cost` | 1—3 | 拒绝/否定时要不要留面子缓冲 |
| `conclusion_position` | early / after_context / late | 结论放第几句 |

当前预设：英语（高直接、低敬语、结论前置）、中文（中直接、中敬语、先背景）、日语（低直接、高敬语、结论最后）、韩语（中直接、高敬语、结论最后）、德语（高直接、低敬语、结论前置）。

语气与对象只是对这四个维度的加减，然后夹到 1—3：

- `tone`：`polite`（更稳妥）/ `direct`（更直接）/ `close`（更亲近）。
- `relation`：`professor` / `manager` / `client` / `peer` / `friend`；对象优先于语气。

**加一门语言 = 加一条配置**：在 `LANGUAGES` 里补一行，把语言代码加进 `TETHER_LANGUAGES`（例如 `TETHER_LANGUAGES=zh,en,ja`），重启即可。接口、提示词、前端下拉框都会自动跟着变，不需要改代码。未在 `TETHER_LANGUAGES` 里的语言会被接口拒绝（400）。

同一句「拒绝客户今晚的追加修改」，只换目标语言，结构会自己变：

- 英语：结论第一句 → 一层缓冲 → 给替代时间（`I'm afraid I'm not able to work on the revision tonight…`）。
- 日语：先致意 → 转述对方请求 → 说明今晚困难 → 请求改到明早（`…進めさせていただけますと助かります`）。

这不是提示词里写死的「英美习惯」，而是四维参数和 `guidance` 一起进模型的结果。

## 输出

```json
{
  "text": "主版本",
  "target_lang": "en",
  "intent": "share|ask_listening|ask_space|ask_advice|unclear",
  "cultural_notes": ["最多两条"],
  "alternatives": [{"tone": "direct", "text": "另一种语气"}],
  "safety": "ok"
}
```

服务端校验：场景/语气/对象必须在白名单内；`details` 不认识的字段直接 400；备选版本必须与主版本不同、语气不同、长度不超过 1200，且逐条过一遍临床表述检查。命中「诊断、药物、治疗」一类词整条丢弃，宁可不给，也不给错。

## 不做的事

- 不替用户发送，不存进账号（结果只在当前页面）。
- 不推断用户的人格、关系或心理状态。
- 不添加用户没有填的事实：时间、原因、承诺都只能来自槽位。
- 不做临床建议；危机表达仍走危机资源入口。

# 反向：听懂对方说了什么

入口在同一张卡片的第二行：「对方的话没看懂？」。接口 `POST /api/expression/interpret`。

只往前写东西的产品只解决一半问题：对方那句话让你不舒服，你既不确定他是不是这个意思，也不知道该怎么接。这一半不做，「跨语言」就只是翻译器。

## 输入

| 字段 | 说明 |
|---|---|
| `text` | 对方发来的那句，1—500 字符 |
| `source_lang` | 对方用的语言，`zh` / `en` |
| `target_lang` | 用哪种语言解释，`zh` / `en` |
| `relation` | 谁说的：professor / manager / client / peer / friend |

## 输出

```json
{
  "meaning": "字面上说了什么",
  "tone": "warm|neutral|tense|harsh|ambiguous",
  "subtext": "可能的潜台词（必须带不确定）",
  "replies": [{"tone": "polite", "text": "可以直接回的一句"}],
  "cultural_notes": ["最多两条"],
  "target_lang": "zh",
  "safety": "ok"
}
```

## 三条硬规则

1. **事实与推测分栏。** `meaning` 只写字面，`subtext` 必须写成「可能是」，且整份输出在界面上永远带一句「语气是推测，重要的事直接问」。
2. **不评价用户、不判断对方人格。** 提示词明确禁止推断动机、关系状态和心理状态。
3. **整条拒绝优先。** 解读和回复都会被用户直接看、直接发，任何一处命中临床表述，整份结果作废，宁可让用户重试。

## 危机表达

如果这句话本身含威胁、自伤或危机信息，不解读潜台词，直接提示确认对方状态并联系当地支持资源——这条写在提示词里，也写在输出的使用说明里。

## 可评测的指标

这些指标用来证明「跨文化语用」不是口号：

- **采纳率**：生成后点了复制 / 生成次数。
- **二次修改率**：复制后回来重新生成的次数。
- **语气保持率**：同一槽位换 `tone` 后，结论位置与致歉强度是否按预期变化。
- **语言合规率**：备选版本被安全校验丢弃的比例。

建议先人工标注 30—50 条真实场景（留学生、跨境团队），再对比通用模型基线，报告上述四项而不是「感觉更自然」。
